# Shell and mise

## mise

`home/dot_config/mise/config.toml` manages the runtimes (Go, Node, Java, Python/uv, Terraform/OpenTofu, kubectl…). The `postinstall` hook runs `after-install.sh`, which regenerates the static zsh completions in `${XDG_CACHE_HOME:-$HOME/.cache}/zsh/completions` — a directory already in the `fpath` of `dot_zshrc.tmpl` and **not** managed by brew.

It does not write to `$(brew --prefix)/share/zsh/site-functions`: several files there are symlinks into the Cellar or inside an `.app` bundle (`_gh`, `_mise`, `_docker`), and a redirect would overwrite them. For the same reason the script covers **only the tools managed by mise**: those installed by brew or by a cask already ship their own completions.

When adding a tool with its own completions, add a `_gen _<name> <command> …` line. The helper discards output that does not start with `#compdef`: without that line compinit never binds the file to the command, and the completion would stay inert with no error. This is the case of `npm`, which needs no line at all: zsh already ships one in `/usr/share/zsh/*/functions/_npm`. `terraform`, `terragrunt` and `tofu` do not generate zsh scripts: they use the bash `complete -C` protocol, enabled in `dot_zshrc.tmpl`.

## Shell

`home/dot_zshrc.tmpl` contains options, history, completion, aliases and functions — but **no tool init**. Starship, Atuin, zoxide, direnv, mise and fzf are initialized in the `inline` blocks of `home/dot_config/sheldon/plugins.toml`, loaded by `eval "$(sheldon source)"`. To add or change how a tool is activated, edit `plugins.toml`, not `dot_zshrc.tmpl`.

The split with `after-install.sh` is clear-cut: `plugins.toml` holds the plugins from git repos and the **session integrations** (prompt, `precmd`/`chpwd` hooks, widgets), which must run in every shell; `after-install.sh` holds the **completions generated by a binary versioned by mise**, which as static files cost nothing at startup and are regenerated only when the version changes.

Binding order in `dot_zshrc.tmpl`: `fpath` → `sheldon source` → `compinit`. Moving `compinit` before sheldon loses the plugin completions — silently: their `fpath` entries are present, but no completion gets bound.
